6// Mendler-style catamorphism over Free (design doc's Section 5 forward
7// reference; FD4): a NEW consuming fold, distinct from mendler.hpp's mcata
8// (Fix-only, const&). Free<F,A> has two constructors -- Pure a | Roll layer
9// -- so its Mendler algebra is two callables, not mcata's one: pure_alg
10// handles the Pure leaf, phi handles a Roll layer exactly the way mcata's
11// own phi does (it receives the recursive call and the layer, and decides
12// which children -- if any -- to fold via that call). Exactly as
13// mendler.hpp documents for mcata/mhisto: **no functor_typeclass<F>
14// instance is ever looked up here** -- phi applies `recurse` to whichever
15// children it likes, by convention, not by any enforced rank-2 discipline
16// (C++ cannot express that any more here than mendler.hpp's own mcata can).
17//
18// Equations:
19// mcata_free (p, phi) (Pure a) = p a
20// mcata_free (p, phi) (Roll l) = phi (mcata_free (p, phi)) l
21//
22// Consuming, and BY VALUE (not const&, unlike mcata): this fold exists for
23// the S07 interpreter, where Result may be a coroutine type (e.g.
24// beman::task<A> -- this header itself has no beman dependency and knows
25// nothing about that). A coroutine's frame only safely owns values that
26// arrive as genuine, direct parameters -- moved/copied into the frame at
27// the point of the call -- never a value merely *referenced* from an
28// enclosing native stack frame, which may already be gone by the time the
29// coroutine resumes past a suspension point (the classic "coroutine +
30// capturing lambda" lifetime hazard: a capturing lambda's closure is a
31// temporary, destroyed at the end of the full-expression that created it,
32// while the coroutine it produced may still be suspended). mcata's Fix
33// traversal never hits this: it is synchronous top-to-bottom, so a const&
34// algebra never outlives the single native call stack holding it. Free's
35// traversal makes no such promise once Result's own callables may suspend,
36// so pure_alg/phi are taken BY VALUE here, and `recurse` -- the callable
37// phi is handed -- closes over its OWN owned copies of them, by value, not
38// by reference. That makes every value phi can hand to a coroutine
39// (`recurse` itself included) fully self-contained, regardless of when or
40// where it is actually invoked -- FD4's capture-ownership rule, in
41// coroutine clothing.

51/** mcata_free :: (a -> c) -> (forall y. (y -> c) -> f y -> c) -> Free f a -> c
52 * @tparam Result the fold's result type (design D5: explicit)
53 * @param pure_alg called as pure_alg(a): the Pure-leaf case, `a` an A&&.
54 * @param phi called as phi(recurse, layer): `recurse` is a callable
55 * Free<F,A>&& -> Result (mcata_free, partially applied);
56 * `layer` is F<Free<F,A>>&&, the Roll's outermost layer.
57 * phi decides which children (if any) to fold via
58 * `recurse` -- no functor_typeclass<F<...>> instance is
59 * consulted here.
60 */
61template <class Result, template <class> class F, class A, class PureAlg,
62 class MAlgebra>
63constexpr auto mcata_free(PureAlg pure_alg, MAlgebra phi, Free<F, A> &&prog)
64 -> Result {
65 if (is_pure(prog)) {
66 return std::invoke(pure_alg, std::get<A>(std::move(prog.node)));
67 }
68 auto layer = std::get<F<Free<F, A>>>(std::move(prog.node));
69 auto recurse = [pure_alg, phi](Free<F, A> &&child) -> Result {
70 return mcata_free<Result, F, A>(pure_alg, phi, std::move(child));
71 };
72 return std::invoke(phi, recurse, std::move(layer));
73}
